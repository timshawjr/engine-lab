# RAG Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a seventh booth page that answers questions about NIST SP 800-82r4 by retrieving passages from the PDF and generating a grounded answer on the GPU, with the cited passages always visible.

**Architecture:** The PDF is extracted and embedded **once, at build time**, into a baked index (`corpus.json` + `index.npy`). At runtime the app does only three things on the GPU: embed the query, cosine-rank the baked matrix, and generate an answer. A `QThread` worker owns the two OpenVINO GenAI pipelines and emits Qt signals, so the 2.1 s mean answer never touches the UI thread. The page always shows the retrieved passages beside the answer.

**Tech Stack:** PySide6, `openvino-genai==2026.4.0.0` (pinned to match the existing `openvino==2026.4.0`), numpy. `pypdf` is **build-time only** (dev venv), never a runtime dependency.

**Spec:** `bench_report.md` (RAG spike section) and `docs/superpowers/plans/2026-10-02-rag-page.md` §Measured baseline below. This plan carries every measured number it depends on; none of them may be re-guessed.

### Configuration that must not regress

Four settings are load-bearing. Each was found by a silent failure, not an error:

1. **`pooling_type=LAST_TOKEN`.** GenAI defaults to `CLS`. On a causal decoder this returns **byte-identical vectors for different questions** (query-query cosine 1.0000) and retrieval silently returns the title page. Score spread improves 0.0025 → 0.1145 with `LAST_TOKEN`. **This must have a regression test.**
2. **`padding_side="left"`.** Required so last-token pooling reads a real token.
3. **`query_instruction`** set to the Instruct/Query prefix below.
4. **`apply_chat_template=False`** plus an **empty think block** prefill (`<think>\n\n</think>\n\n`). Qwen3 otherwise spends the entire token budget on reasoning and returns no answer.

**Never use `padding_side="left"` with the NPU.** Measured: the NPU returns **all-zero vectors**, silently. Retrieval would score against zeros and show plausible nonsense.

### NPU status — the honest label

The RAG path is **GPU-only**, measured not assumed:

- LLM on NPU: fails to compile (`MultiClusterStrategyAssignment Pass failed`).
- Embedding on NPU: compiles, returns finite vectors, **1170 ms/query vs 16 ms on GPU (73× slower)**.

The UI must say **GPU**. It must never claim NPU for this page. A reranker (`Qwen3-Reranker-0.6B-seq-cls-fp16-ov`, 1.19 GB) was evaluated and **rejected**: citation accuracy fell 4/5 → 2/5 and it promoted abbreviation lists over real answers. Do not reintroduce it.

## Global Constraints

- No network at runtime (AGENTS.md §7). Corpus and models ship on disk.
- Never touch widgets from a non-UI thread (AGENTS.md §11). The worker uses Qt signals only.
- Never crash in front of a customer (AGENTS.md §12). One failed question marks that request failed; the page stays alive.
- Layout tokens live in `app/theme.py` (AGENTS.md §10). No metric literals in UI code.
- No unsourced number on screen (AGENTS.md §2). Timings shown must be the ones actually measured for that request.
- `config/models.json` and `config/platform_profiles.json` are verified data (AGENTS.md §6).
- Ask before adding any runtime dependency. GenAI was approved by the user on 2026-10-02; nothing else was.

## Review Focus

1. **A question with no supportable answer.** The model must return `NOT IN PROVIDED PAGES` and the UI must show it as a gap, never as an answer. This is the failure the whole abstention design exists to prevent.
2. **Empty / whitespace query.** Must be rejected before any inference; must not spend 2 s to return nothing.
3. **Clicking Ask twice quickly.** The second request must not race the first; the worker must drop or queue it.
4. **Missing or truncated model files.** A partial download must produce a clear on-screen "model missing" state, not a crash on first question.
5. **Corpus and index out of step** (chunks count ≠ index rows). Must be detected and reported, not silently mismatched.

- [ ] **Step 3: Implement `tools/build_rag_corpus.py`**

Port the measured extractor. Exported signatures:

```python
def marginal_line_numbers(lines: list[str]) -> set[int]
def clean_page(text: str) -> str
def chunk(text: str, target: int = 240, overlap: int = 40) -> list[str]
def main(argv: list[str] | None = None) -> int
```

**Import `pypdf` inside `main()`, never at module level.** The pinned `.venv` deliberately does not contain `pypdf` — it lives only in the dev venv — so a top-level import would make this module unimportable from every test in the suite. The cleaning helpers above must be importable with only the standard library.

`marginal_line_numbers` collects **every** run of three or more consecutive integers, not only the longest — that was the bug that left 4066–4073 in the text. The threshold of three is deliberate: a run of two is far more likely to be a coincidental consecutive pair in body text (figure numbers, standards references) than a genuine pair of marginal line numbers, and dropping to two strips real content.

The `main` flow: `PdfReader` → `extract_text()` (plain mode; layout mode mangles justified text) → `clean_page` → `chunk` → write `models/rag/corpus.json` as `{"document": ..., "chunks": [{"page": int, "text": str}, ...]}`, then embed each chunk in batches of 16 and write `models/rag/index.npy` as float32 `(len(chunks), 1024)`.

Use `TextEmbeddingPipeline.Config` with `pooling_type=LAST_TOKEN`, `padding_side="left"`. Batch size **16**, not 567: one `embed_documents` call over the whole corpus exhausts GPU memory (`CL_OUT_OF_RESOURCES`).

This script runs under the **dev venv** (it needs `pypdf`), like the existing `tools/build_clip_zero_shot.py`. Print and assert the counts 321 pages / 595 chunks / 107,496 words; if they differ, say so loudly rather than proceeding.
